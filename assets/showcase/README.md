# Showcase videos

This folder holds the 9 qualitative comparison videos of MoPlan against the untrained base model, with the inputs
and settings needed to generate every panel again.

Each case compares two models on the same first frame, the same text and the same random seed:

- **MoPlan**: the final model, that is the Stage-1 motion predictor plus the Stage-2 generator
  (weights in `$MOPLAN_WEIGHTS`).
- **Wan2.2**: the untrained Wan2.2-I2V-A14B, run through the same diffusers pipeline without LoRA, adapter or
  motion condition (`--base`).

When a recorded continuation exists, it is shown as the left panel ("Real video").

The videos are shown on the site page (`index.html` at the repository root, generated by `showcase.py build`).

## Folder layout

Each case lives in `<NN>_<id>/`:

| file | content |
|---|---|
| `comparison.mp4` | the published side-by-side video (448x256 per panel, labels burned in) |
| `poster.jpg` | a frame of the composite at 0.75 of its length |
| `strip.png` | six frames over time for each panel |
| `first_frame.png` / `first_frame.jpg` | the generation input: a byte-identical copy (cases 1–7), or a pixel-identical copy with the PNG text and EXIF chunks removed (cases 8 and 9) |
| `meta.json` | title, caption, benchmark, sample ids, prompts, seeds, protocol, panel layout, commands, reference hashes |

In `meta.json`:

- `layout.rows[].panels[]` lists the panels from left to right.
- `arm` is `real` (recorded video), `base` (untrained Wan2.2), `moplan` (final model) or `still` (a held frame).
- Every generated panel has a `prompt`, a `seed`, the `command` that generates it and a `reference` hash.
  `reference.verifiable` is `false` when the hash is of a file that `generate.py` does not write (cases 8 and 9, see
  below).
- `first_frame.source` and `first_frame.attribution` give the origin, licence and any modification of the first
  frame.

## Generation protocols

Both `generate.py` protocols use the Wan2.2-I2V-A14B Diffusers pipeline with these settings:

- the UniPC scheduler of the pipeline (flow shift 3.0) with 30 steps;
- guidance scale 5.0 for both experts, boundary ratio 0.9;
- the official Wan2.2 negative prompt, and text embeddings of length 512;
- the first frame resized to 448x256 with LANCZOS (stretched, no crop).

| | MoProbe protocol (`--protocol moprobe`) | Physics-IQ (`--protocol physics_iq`) |
|---|---|---|
| cases | 1–3, 8, 9 | 4–7 |
| first frame | cases 1–3: 1280x720 PNG, the source frame letterboxed onto a 16:9 canvas; cases 8 and 9: the 1280x704 RigidBench frame, no canvas | 3840x2160 Physics-IQ switch frame (the file of the original release, also used by Physics-IQ Verified) |
| prompt | case 1: an instruction pair from `data/moprobe/moprobe_h_rows.jsonl`; cases 2 and 3: the PisaBench prompt; cases 8 and 9: the RigidBench prompt plus one sentence (below) | the Physics-IQ best-practice description (`descriptions/best_practice/descriptions_base.csv`) |
| frames, fps | 37 frames at 7 fps; cases 8 and 9: 17 frames at 7 fps (`--frames 17 --fps 7`) | 41 frames at 8 fps, trimmed to the first 5 s (40 frames) |
| seed | `42 + crc32(sample_id) % 100000` | `42` for every video |

The protocol name `moprobe` only names the generation settings. Case 1 uses a Something-Something v2 validation frame
that is not part of the MoProbe-H set: the item check removed it (`data/moprobe/rejected_frames.json`).

Both models of a case always use the same seed. The noise comes from `torch.Generator("cuda").manual_seed(seed)`.

For the two RigidBench cases (8, 9), the generator prompt is the benchmark prompt followed by
" Static shot with no camera movement.". This sentence is appended whenever the benchmark text itself asks for a
static camera. The exact prompt of every panel is in `meta.json`.

These two cases come from a separate RigidBench generation run with the settings above: the Wan2.2 default negative
prompt and the appended sentence. They are not from the official-protocol RigidBench evaluation in
`docs/EVALUATION.md`, which uses the benchmark prompt verbatim and RigidBench's official negative prompt (`run_note`
in `meta.json`).

## Regenerating the panels

Set up the environment and the weights as described in the top-level README:

- `WAN_MODEL_DIR` is needed for both models.
- `MOPLAN_WEIGHTS` and the Stage-1 dependencies are needed for MoPlan.

Then run the commands from the repository root:

```bash
python assets/showcase/showcase.py commands                 # all 20 generated panels
python assets/showcase/showcase.py commands --case 4        # one case (1-9; another number is an error)
python assets/showcase/showcase.py commands --arm base > base.sh && bash base.sh
```

Each command writes `out/showcase/<NN>_<id>/<key>.mp4`, the frame array `<key>.npy` and a `<key>.json` sidecar.
The `<key>` is the panel key in `meta.json` (`moplan`, `base`, `A_moplan`, `B_base`, ...). For Physics-IQ the mp4 is
the trimmed 40-frame clip; add `--save-intermediates` to keep the raw 41-frame clip under `<key>.work/raw/`.

### Checking bit-exactness

The `reference` of each generated panel holds the sha256 of the output of the original run:

- **Cases 1–3 (MoProbe protocol):** the hash is of the uint8 frame array `[37, 256, 448, 3]` saved with
  `numpy.save`.
- **Cases 4–7 (Physics-IQ):** the hashes are of the raw 41-frame mp4 (imageio, libx264, quality 8, 8 fps) and of
  the trimmed mp4 (`ffmpeg -t 5`, 40 frames).
- **Cases 8 and 9 (RigidBench):** the hash (`export_sha256`) is of the 1280x704 mp4v evaluation export of the 17
  frames. `generate.py` does not write this file, and no hash of the 448x256 frame array is recorded, so these panels
  cannot be checked bit-for-bit.

To check the panels, run:

```bash
python assets/showcase/showcase.py verify out/showcase
```

`verify` compares `<key>.npy` (cases 1–3) and `<key>.mp4` (cases 4–7, raw or trimmed) with the references. It
prints `MATCH`, `DIFFERS` or `NO-REF` for each file it finds and `NOT-VERIFIABLE` for the four panels of cases 8 and 9.
The exit code is 1 only when a file differs.

The original runs used one H100 80GB per process with torch 2.5.1 and diffusers 0.38.0. A different GPU type or
library version may change the result in the last bits. Two inputs of MoPlan can also differ from the original batch
runs (see `docs/INFERENCE.md`, "Bit-exactness: known sources of difference"):

- `generate.py` reruns SAM 2.1 on the first frame unless `--masks` gives a k16 mask file. For the Physics-IQ cases
  (4–7) the released mask builder is not expected to reproduce the reference masks: they were made by an older
  version of the builder that is not in this repository (see `docs/EVALUATION.md`, "Bit-exact reproduction").
  Their reference masks are therefore included as `masks_k16.pt` in each of these case folders, and the MoPlan
  commands pass them with `--masks`. Without `--masks`, `verify` is expected to report `DIFFERS` for these MoPlan
  panels; this is not a hardware difference. The MoProbe cases (1–3) run SAM 2.1; the released builder was checked to
  rebuild their reference masks.
- `generate.py` encodes the Stage-1 caption next to the empty prompt only, while the batch runs encoded it in batches
  of 4 with other captions. Pass the batch manifest with `--stage1-text-manifest` (and `--stage1-text-shard 0/1`) to
  reproduce those batches.

Apart from the four Physics-IQ mask files, the original k16 masks and the batch manifests are not part of this
repository.

### Composite videos

The composites are re-encodes (libx264 crf 24) of the generated panels and the real clips, with burned-in labels, so
they are not byte-reproducible. Compare regenerated panels with the per-panel references, not with
`comparison.mp4`.

The following do not use the generation input directly:

- **Real panels:** these are the source videos. Each one is resampled to the clip frame rate and scaled to 448x256.
  - SSv2 clips start at the frame the first frame was taken from.
  - Physics-IQ takes start at the switch frame (3.0 s).
- **"First frame" still (case 1):** the left panel of row B holds frame 0 of the row A MoPlan clip.

To check the assets against `meta.json`, run:

```bash
python assets/showcase/showcase.py check
```
